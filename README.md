# PersDataGate

Минимальный локальный шлюз: псевдонимизирует документ и промпт перед OpenAI и восстанавливает значения в ответе.

## Запуск CPU или CUDA

Нужны Docker и Docker Compose 2.30+; локально проверен Compose 5.5.1. По умолчанию используется CUDA 12.8 и NVIDIA GPU, доступный из Linux-контейнеров. CPU запускается дополнительным Compose-файлом и не требует NVIDIA.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# Заполните OPENAI_API_KEY и OPENAI_MODEL в .env локально.
# CUDA (режим по умолчанию):
docker compose up -d --build
# Либо CPU:
docker compose -f compose.yaml -f compose.cpu.yaml up -d --build
```

Откройте http://localhost:8090. Compose задаёт `DEVICE=cuda` или `DEVICE=cpu`; при запуске Python вне Compose настройка читается из окружения и по умолчанию равна `cuda`. Другие значения отклоняются. В CUDA-режиме отсутствие GPU завершает запуск ошибкой; автоматического перехода на CPU нет. Внутренний тайм-аут — 600 секунд (`PSEUDONYMIZER_TIMEOUT_SECONDS`), OpenAI — 120 секунд.

У обоих режимов один сервис и API. GLiNER2.5 распознаёт персональные данные, общая локальная Qwen связывает имена и выбирает словоформы. Модель выбирается в `.env`: `LOCAL_LLM_MODEL=Qwen/Qwen3-1.7B` по умолчанию; также доступна `Qwen/Qwen3-4B-Instruct-2507`. Ревизии обеих моделей закреплены в коде, фактически выбранная модель записывается в журнал GUID. После изменения настройки пересоздайте pseudonymizer. Qwen загружается один раз: FP16 на CUDA, FP32 на CPU. Переключение режима или модели сбрасывает таблицы замен. Docker-том `model-cache` общий и хранит веса GLiNER2.5 и Qwen. Без ключа и модели OpenAI отправка заблокирована.

Базовые пакеты pseudonymizer устанавливаются отдельными `RUN pip install` слоями в Dockerfile. Сначала ставится точный CPU- или CUDA-вариант PyTorch из соответствующего официального индекса; остальные зависимости устанавливаются по отдельности из PyPI. Так Docker повторно использует слои неизменившихся пакетов при пересборке. У CPU-образа нет зависимостей NVIDIA. Режим работающего сервиса должен совпадать с режимом собранного образа.

Дополнительный `pseudonymizer/requirements.txt` подключён с диска проекта только для чтения. При старте pip устанавливает недостающие зависимости и проверяет совместимость. Уже установленные подходящие версии остаются на месте. Версии всех базовых пакетов зафиксированы в constraints внутри образа: дополнительный файл не может незаметно заменить PyTorch, CUDA или другие базовые библиотеки.

Кэш pip не используется. Пересоздание контейнера из готового образа сохраняет базовые зависимости; пересборка без Docker-кэша скачает их заново. Старый каталог `.deps/pip-cache` больше не подключается. Том с весами моделей остаётся отдельно: `docker compose down -v` удаляет его.

## Обновление зависимостей

Для нового дополнительного пакета добавьте закреплённую версию в `pseudonymizer/requirements.txt`, затем перезапустите сервис:

```powershell
docker compose restart pseudonymizer
```

Для изменения базовых версий правьте файл соответствующего режима и пересоберите образ:

```powershell
# CUDA:
docker compose up -d --build pseudonymizer
# CPU:
docker compose -f compose.yaml -f compose.cpu.yaml up -d --build pseudonymizer
```

Дополнительные зависимости, установленные при старте, сохраняются при перезапуске того же контейнера и повторно устанавливаются при его пересоздании. Удаление строки из дополнительного файла не удаляет уже установленный пакет; для чистого окружения пересоздайте контейнер. Скрипты подготовки кэша больше не нужны и удалены.

## Проверка запуска

CUDA:

```powershell
docker compose ps
docker compose logs --tail 30 pseudonymizer
docker compose exec -T pseudonymizer python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

CPU:

```powershell
docker compose -f compose.yaml -f compose.cpu.yaml ps
docker compose -f compose.yaml -f compose.cpu.yaml logs --tail 30 pseudonymizer
docker compose -f compose.yaml -f compose.cpu.yaml exec -T pseudonymizer python -c "import torch; print(torch.__version__, torch.version.cuda)"
```

Дождитесь `healthy`. У CPU ожидаются версия с `+cpu` и `torch.version.cuda == None`, у CUDA — `+cu128` и доступный GPU. У внутреннего `/health/ready` поле `device` показывает выбранное устройство. Затем в обоих режимах проверьте синтетические RU/DE-примеры:

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_model.py | docker compose exec -T web python -
```

Дополнительно проверьте собственные документы и время обработки длинных текстов. `docker compose down` сохраняет том модели; не добавляйте `-v`, если он нужен. Для CPU применяйте те же `-f` параметры. После изменения ключа/модели OpenAI пересоздайте web с соответствующей командой Compose. Порт меняется через `WEB_PORT` в `.env`.

## Два сервиса

- `web`: FastAPI, статический интерфейс, диспетчеризация и OpenAI Responses API. Порт опубликован только на `127.0.0.1`. Документ и промпт объединяются с разделителями и обрабатываются одним вызовом.
- `pseudonymizer`: GLiNER2.5 `fastino/gliner2.5-multi-v1`, Qwen из `LOCAL_LLM_MODEL` (закреплённые ревизии в `pseudonymizer/local_llm.py`), pymorphy3, форматные правила и приватные таблицы замен. Нет опубликованного порта и ключа OpenAI. Один процесс; инференс последовательный.

Одна кнопка выполняет `anonymize → OpenAI → deanonymize`. Справа видны семь этапов: найденные персональные данные (GLiNER/правила), группы связанных имён и варианты упоминаний, псевдонимизированный текст, точный запрос OpenAI, полученный ответ, замены и словоформы для каждого вхождения маркера, восстановленный ответ. Подробности сворачиваются; оба ответа видны одновременно. Этапы появляются после завершения HTTP-запроса. При сбое OpenAI или восстановления уже полученные этапы сохраняются в интерфейсе.

Web запрашивает `include_steps: true` у обоих внутренних методов. По умолчанию API не возвращает подробности. Эти сведения возвращаются локальному интерфейсу и сохраняются в журнале пайплайна; в запрос OpenAI и браузерное хранилище они не включаются.

## Журнал пайплайнов

Каждая обработка получает GUID, который выводится под кнопкой: `Готово · GUID: …` или рядом с ошибкой. Оба сервиса используют один GUID через внутренний заголовок `X-Pipeline-ID`. GUID возвращается также в поле `pipeline_id` ответа API. В консоли сервера выводятся GUID и названия этапов.

Полные записи сохраняются в `logs/pipelines/<GUID>/web.jsonl` и `pseudonymizer.jsonl`: исходный документ и промпт, объединённый ввод, фрагменты и ответы GLiNER, правила и выбранные сущности, решения о связывании, канонические имена и варианты, таблица замен, системные инструкции и ввод Qwen, её сырой и разобранный ответ, точный запрос и полный ответ OpenAI, выбранные словоформы, восстановленный текст и ошибки. Каждая JSONL-запись содержит время UTC, GUID, сервис, этап и данные. Записи добавляются по мере выполнения; завершённые этапы остаются и при сбое.

Папка подключена к обоим контейнерам с диска проекта и переживает пересоздание контейнеров и очистку Docker-кэша. Она исключена из Git и контекста сборки. Логи содержат исходные персональные данные и не удаляются автоматически. Ключ API и заголовки авторизации сервис не журналирует. При невозможности записать журнал запрос завершается ошибкой.

Посмотреть все этапы по GUID в порядке времени:

```powershell
python ./scripts/show_pipeline.py <GUID>
```

Можно передать GUID для диагностики: соответствующий журнал находится непосредственно в папке проекта. Для запросов, выполненных до внедрения журналирования, полный журнал отсутствует.

В OpenAI отправляется обработанный текст и фиксированная инструкция сохранять маркеры. Таблица соответствий и `mapping_id` не передаются. Используется `store=false`, без `temperature`, streaming и автоматических повторных отправок. `store=false` отключает хранение ответа для последующего извлечения API, но сам по себе не означает Zero Data Retention.

## Внутренний API

`POST http://pseudonymizer:8000/anonymize`

```json
{"text": "Иван Петров: ivan@example.org"}
```

Возвращает `mapping_id`, `text` с маркерами вида `⟦PERSON_<случайный-id>_1⟧`, `expires_at` в UTC и `warnings`. У уверенно связанных имён одинаковый маркер во всех фрагментах документа. Предупреждения не включают исходные имена и не передаются OpenAI.

`POST http://pseudonymizer:8000/deanonymize`

```json
{"mapping_id": "UUID из anonymize", "text": "Ответ с неизменёнными маркерами"}
```

Возвращает `text` и `warnings`. Восстановление выполняется одним проходом только для точных известных маркеров; неизвестные маркеры остаются без изменений. При неизвестной или истёкшей таблице — `404` с `detail: mapping_not_found`.

Таблицы живут в памяти **30 минут с момента создания**, повторное чтение не продлевает срок. Перезапуск pseudonymizer удаляет все таблицы. Для одной таблицы можно восстанавливать несколько ответов до истечения срока.

`GET /health/ready` у pseudonymizer проверяет загрузку модели и возвращает `device`; `GET /health` у web сообщает состояние конфигурации без значений ключа. Внешний API диспетчера: `POST /api/process` с `document` и `prompt`.

## Границы MVP

Только вставка текста, без файлов, OCR, истории и авторизации. Максимальный суммарный текст с разделителями — 50 000 символов. Внутренние HTTP-вызовы — 600 секунд, OpenAI — 120 секунд.

GLiNER2.5 (мультиязычная модель с boundary-архитектурой) ищет имена, адреса, даты рождения, номера документов и банковские идентификаторы. Правила дополняют email, телефоны, IBAN и номера документов по явному контексту. Общие даты, организации и географические названия вне адресов не входят в целевой набор. Длинный текст разбивается на перекрывающиеся фрагменты; все PERSON-упоминания затем рассматриваются вместе.

Для имён GLiNER2.5 получает метку `person` и порог 0,10. Для остальных типов сохраняется порог 0,45: модель возвращает кандидатов с 0,10, затем сервис фильтрует их по типу. В журнале видны оба порога и отклонённые кандидаты. Более низкий порог для PERSON уменьшает пропуски, но может добавить лишние замены; это нужно проверять на собственных документах.

Для русского и немецкого Qwen сравнивает допустимые пары имён, получая в каждом запросе документ целиком и два сравниваемых упоминания с их позициями. Фрагменты по 160 символов больше не используются для связывания. Инициалы и фамилия могут связываться с полным именем; неоднозначные сокращения остаются отдельно с предупреждением. Местоимения и должности не связываются. Максимум токенов берётся из `model.config.max_position_embeddings`: у закреплённой Qwen3-1.7B это 40 960. Под ответ зарезервированы 256 токенов; документ, инструкции и JSON вместе должны помещаться в оставшиеся 40 704. При превышении сервис возвращает ошибку с числом токенов и лимитом, без обрезки и без отправки в OpenAI. Большой контекст требует больше памяти и времени. При слишком большом числе кандидатов упоминания сохраняются отдельно с предупреждением.

Для связывания и выбора формы генерация ограничена конечным набором допустимых JSON-ответов на уровне токенов. Qwen не может добавить Markdown, другое имя поля или произвольное написание имени. Семантическая неопределённость остаётся возможной: доступны `unknown` для связи и `null` для формы.

При восстановлении Qwen выбирает форму для конкретного места ответа из конечного набора: русские формы строит pymorphy3, для немецких имён предусмотрена притяжательная форма. Имя раскрывается до полного, только если оно было обнаружено в документе. Неуверенный или недопустимый выбор оставляет маркер с предупреждением. Остальные значения восстанавливаются точно. Побуквенный round trip для PERSON больше не является критерием: сокращения могут раскрыться, а падеж — измениться.

Немецкий блок получателя `An → имя отдельной строкой → улица/ADDRESS-маркер → пятизначный индекс и город` восстанавливает латинское имя в исходной форме по структуре адреса, без выбора падежа Qwen. Это правило не применяется к произвольному тексту или русским именам. В таблице восстановления показывается причина: адресное поле, выбор Qwen, `null`, ошибка модели или отсутствие допустимых форм.

Распознавание может пропускать персональные данные или заменять лишнее. Это псевдонимизация, а не гарантия полной анонимности: контекст документа также может идентифицировать человека. Изменённые моделью маркеры автоматически не угадываются. Тексты и таблицы сохраняются в журнале пайплайна; в браузерное хранилище не записываются. Содержимое страницы сохраняется только до её обновления.

## Тесты

После сборки Web тесты можно запускать в одноразовом контейнере Python 3.11:

```powershell
docker run --rm --mount "type=bind,source=$PWD,target=/checks" -w /checks persdatagate-web sh -c "python -m pip install -q -r requirements-dev.txt && python -m pytest -q"
```

Для локального запуска используйте Python 3.11, виртуальное окружение и `requirements-dev.txt`.

Unit/API-тесты используют подменённые детектор и OpenAI и не требуют Torch, GPU, ключа или платных API-вызовов. CPU/CUDA, реальная модель и качество распознавания проверяются отдельно внутри Docker.

После готовности pseudonymizer выполните оценку на синтетических русских и немецких примерах:

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_model.py | docker compose exec -T web python -
```

Скрипт сообщает точные и частичные совпадения, пропуски и лишние замены, отдельно проверяя обратное восстановление. Успешный exit code означает точный round trip, а не стопроцентное качество распознавания.

Проверка 2026-10-08 на RTX 3080 Ti Laptop GPU: 22 unit/API-теста прошли. В четырёх синтетических RU/DE-примерах распознаны все 14 ожидаемых значений, обратное восстановление точное. Осталось лишнее срабатывание на отдельном слове «Москва». Это небольшой проверочный набор, а не оценка качества на реальных документах. Отчёт можно получить указанной командой; локальный результат сохранён в `artifacts/model-evaluation.json`.

Живой вызов OpenAI не проверен. Цепочка диспетчеризации проверяется с подменённым HTTP-транспортом настоящего SDK OpenAI.

На реальной кэшированной Qwen проверено исправление формата ответа: `Egor Ivanov` / `EGOR IVANOV` связываются в один ID, имя в немецком адресном блоке восстанавливается; разные имена и неоднозначные инициалы остаются раздельными. Это небольшая синтетическая проверка, а не полный набор качества. В русском примере «Письмо адресовано …» модель выбрала родительный вместо дательного; ограничение JSON не гарантирует грамматику. После запуска выполните отдельный набор с ожидаемыми группами упоминаний и формами (без вызовов OpenAI):

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_persons.py | docker compose exec -T web python -
# CPU: добавьте -f compose.yaml -f compose.cpu.yaml после docker compose.
```

Старый `evaluate_model.py` предназначен для оценки детектора и точного round trip; его критерий для PERSON устарел. Проверки с подменённым генератором подтверждают логику и ограничения, но не качество решений Qwen3 1.7B.
