# PersDataGate

Минимальный локальный шлюз: псевдонимизирует документ и промпт перед OpenAI и восстанавливает значения в ответе.

## Запуск CPU или CUDA

Нужны Docker и Docker Compose 2.30+; локально проверен Compose 5.5.1. По умолчанию используется CUDA 12.8 и NVIDIA GPU, доступный из Linux-контейнеров. CPU запускается дополнительным Compose-файлом и не требует NVIDIA.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# Заполните OPENAI_API_KEY и OPENAI_MODEL в .env локально.
# CUDA (режим по умолчанию):
docker compose up -d --build
# Либо CPU:
docker compose -f compose.yaml -f compose.cpu.yaml up -d --build
```

Откройте http://localhost:8090. Compose задаёт `DEVICE=cuda` или `DEVICE=cpu`; при запуске Python вне Compose настройка читается из окружения и по умолчанию равна `cuda`. Другие значения отклоняются. В CUDA-режиме отсутствие GPU завершает запуск ошибкой; автоматического перехода на CPU нет. Внутренний тайм-аут — 600 секунд (`PSEUDONYMIZER_TIMEOUT_SECONDS`), OpenAI — 120 секунд.

У обоих режимов один сервис и API. GLiNER распознаёт персональные данные, общая локальная Qwen3 1.7B связывает имена и выбирает словоформы. Qwen загружается один раз: FP16 на CUDA, FP32 на CPU. Переключение режима пересоздаёт pseudonymizer; таблицы замен сбрасываются. Кэш pip `.deps/pip-cache` и Docker-том `model-cache` общие. Первый запуск скачает также веса Qwen; готовность требует обеих моделей. Без ключа и модели OpenAI отправка заблокирована.

Зависимости устанавливаются при первом старте нового контейнера из `pseudonymizer/requirements.cuda.txt` или `pseudonymizer/requirements.cpu.txt`. Режим и файл зависимостей входят в маркер установленного окружения: при обычном перезапуске того же контейнера установка пропускается. Сборка образа не скачивает пакеты; сервис готов после установки и загрузки модели.

PyTorch устанавливается отдельно с `--no-deps` из официального индекса `cu128` либо `cpu`. Остальные зависимости ставятся с PyPI: это избегает NVIDIA-ссылок с запретом HTTP-кеширования. У CPU-сборки PyTorch нет зависимостей NVIDIA; ранее скачанные CUDA-файлы в общем кэше автоматически не удаляются.

Кэш pip подключён напрямую с диска проекта и переживает очистку кэша Docker и удаление образов. Pip может обращаться в интернет за метаданными; [кэш pip](https://pip.pypa.io/en/stable/topics/caching/) уменьшает повторные загрузки, но не является установкой без сети. Том модели отдельно: `docker compose down -v` удаляет его.

Подготовка кэша необязательна; выполняется в одноразовом Linux-контейнере без запуска сервиса:

```powershell
./scripts/prepare-pseudonymizer-dependencies.ps1 -Device cuda
# Либо CPU:
./scripts/prepare-pseudonymizer-dependencies.ps1 -Device cpu
```

## Обновление зависимостей

Общие диапазоны обновлений заданы в `pseudonymizer/requirements.in`. Кандидат сохраняется отдельно для выбранного режима, рабочие файлы не меняются:

```powershell
./scripts/prepare-pseudonymizer-dependencies.ps1 -Mode Update -Device cuda
# Для CPU укажите -Device cpu; кандидат будет requirements.updated.cpu.txt.
git diff --no-index pseudonymizer/requirements.cuda.txt .deps/requirements.updated.cuda.txt
# После просмотра примените CUDA-кандидат:
Copy-Item pseudonymizer/requirements.cuda.txt .deps/requirements.previous.cuda.txt
Copy-Item .deps/requirements.updated.cuda.txt pseudonymizer/requirements.cuda.txt
docker compose up -d --build --force-recreate pseudonymizer
```

Для CPU аналогично используйте файлы с `cpu` и команду `docker compose -f compose.yaml -f compose.cpu.yaml up -d --build --force-recreate pseudonymizer`. Откат: восстановите соответствующий файл зависимостей из `.deps/requirements.previous.<режим>.txt` и пересоздайте сервис. `Update` выполняет `pip check`, но не проверяет реальную модель. Не запускайте подготовку и установку сервиса одновременно с одним кэшем.

## Проверка запуска

CUDA:

```powershell
docker compose ps
docker compose logs --tail 30 pseudonymizer
docker compose exec -T pseudonymizer python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

CPU:

```powershell
docker compose -f compose.yaml -f compose.cpu.yaml ps
docker compose -f compose.yaml -f compose.cpu.yaml logs --tail 30 pseudonymizer
docker compose -f compose.yaml -f compose.cpu.yaml exec -T pseudonymizer python -c "import torch; print(torch.__version__, torch.version.cuda)"
```

Дождитесь `healthy`. У CPU ожидаются версия с `+cpu` и `torch.version.cuda == None`, у CUDA — `+cu128` и доступный GPU. У внутреннего `/health/ready` поле `device` показывает выбранное устройство. Затем в обоих режимах проверьте синтетические RU/DE-примеры:

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_model.py | docker compose exec -T web python -
```

Дополнительно проверьте собственные документы и время обработки длинных текстов. `docker compose down` сохраняет том модели; не добавляйте `-v`, если он нужен. Для CPU применяйте те же `-f` параметры. После изменения ключа/модели OpenAI пересоздайте web с соответствующей командой Compose. Порт меняется через `WEB_PORT` в `.env`.

## Два сервиса

- `web`: FastAPI, статический интерфейс, диспетчеризация и OpenAI Responses API. Порт опубликован только на `127.0.0.1`. Документ и промпт объединяются с разделителями и обрабатываются одним вызовом.
- `pseudonymizer`: GLiNER `urchade/gliner_multi-v2.1`, Qwen `Qwen/Qwen3-1.7B` (revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`), pymorphy3, форматные правила и приватные таблицы замен. Нет опубликованного порта и ключа OpenAI. Один процесс; инференс последовательный.

Одна кнопка выполняет `anonymize → OpenAI → deanonymize`. Справа видны параметры и полный текст запроса (`instructions` и `input`), исходный текст ответа и восстановленный текст. При сбое восстановления полученный ответ сохраняется в интерфейсе.

В OpenAI отправляется обработанный текст и фиксированная инструкция сохранять маркеры. Таблица соответствий и `mapping_id` не передаются. Используется `store=false`, без `temperature`, streaming и автоматических повторных отправок. `store=false` отключает хранение ответа для последующего извлечения API, но сам по себе не означает Zero Data Retention.

## Внутренний API

`POST http://pseudonymizer:8000/anonymize`

```json
{"text": "Иван Петров: ivan@example.org"}
```

Возвращает `mapping_id`, `text` с маркерами вида `⟦PERSON_<случайный-id>_1⟧`, `expires_at` в UTC и `warnings`. У уверенно связанных имён одинаковый маркер во всех фрагментах документа. Предупреждения не включают исходные имена и не передаются OpenAI.

`POST http://pseudonymizer:8000/deanonymize`

```json
{"mapping_id": "UUID из anonymize", "text": "Ответ с неизменёнными маркерами"}
```

Возвращает `text` и `warnings`. Восстановление выполняется одним проходом только для точных известных маркеров; неизвестные маркеры остаются без изменений. При неизвестной или истёкшей таблице — `404` с `detail: mapping_not_found`.

Таблицы живут в памяти **30 минут с момента создания**, повторное чтение не продлевает срок. Перезапуск pseudonymizer удаляет все таблицы. Для одной таблицы можно восстанавливать несколько ответов до истечения срока.

`GET /health/ready` у pseudonymizer проверяет загрузку модели и возвращает `device`; `GET /health` у web сообщает состояние конфигурации без значений ключа. Внешний API диспетчера: `POST /api/process` с `document` и `prompt`.

## Границы MVP

Только вставка текста, без файлов, OCR, истории и авторизации. Максимальный суммарный текст с разделителями — 50 000 символов. Внутренние HTTP-вызовы — 600 секунд, OpenAI — 120 секунд.

GLiNER ищет имена, адреса, даты рождения, номера документов и банковские идентификаторы. Правила дополняют email, телефоны, IBAN и номера документов по явному контексту. Общие даты, организации и географические названия вне адресов не входят в целевой набор. Длинный текст разбивается на перекрывающиеся фрагменты; все PERSON-упоминания затем рассматриваются вместе.

Для русского и немецкого Qwen сравнивает только допустимые пары имён с локальным контекстом. Инициалы и фамилия могут связываться с полным именем; неоднозначные сокращения остаются отдельно с предупреждением. Местоимения и должности не связываются. Контекст одного запроса Qwen ограничен 8192 токенами вместе с ответом; документ целиком не обрезается. При слишком большом числе кандидатов упоминания сохраняются отдельно с предупреждением.

При восстановлении Qwen выбирает форму для конкретного места ответа из конечного набора: русские формы строит pymorphy3, для немецких имён предусмотрена притяжательная форма. Имя раскрывается до полного, только если оно было обнаружено в документе. Неуверенный или недопустимый выбор оставляет маркер с предупреждением. Остальные значения восстанавливаются точно. Побуквенный round trip для PERSON больше не является критерием: сокращения могут раскрыться, а падеж — измениться.

Распознавание может пропускать персональные данные или заменять лишнее. Это псевдонимизация, а не гарантия полной анонимности: контекст документа также может идентифицировать человека. Изменённые моделью маркеры автоматически не угадываются. Тексты и таблицы не записываются сервисом в файлы, логи или браузерное хранилище; содержимое страницы сохраняется только до её обновления.

## Тесты

После сборки Web тесты можно запускать в одноразовом контейнере Python 3.11:

```powershell
docker run --rm --mount "type=bind,source=$PWD,target=/checks" -w /checks persdatagate-web sh -c "python -m pip install -q -r requirements-dev.txt && python -m pytest -q"
```

Для локального запуска используйте Python 3.11, виртуальное окружение и `requirements-dev.txt`.

Unit/API-тесты используют подменённые детектор и OpenAI и не требуют Torch, GPU, ключа или платных API-вызовов. CPU/CUDA, реальная модель и качество распознавания проверяются отдельно внутри Docker.

После готовности pseudonymizer выполните оценку на синтетических русских и немецких примерах:

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_model.py | docker compose exec -T web python -
```

Скрипт сообщает точные и частичные совпадения, пропуски и лишние замены, отдельно проверяя обратное восстановление. Успешный exit code означает точный round trip, а не стопроцентное качество распознавания.

Проверка 2026-10-08 на RTX 3080 Ti Laptop GPU: 22 unit/API-теста прошли. В четырёх синтетических RU/DE-примерах распознаны все 14 ожидаемых значений, обратное восстановление точное. Осталось лишнее срабатывание на отдельном слове «Москва». Это небольшой проверочный набор, а не оценка качества на реальных документах. Отчёт можно получить указанной командой; локальный результат сохранён в `artifacts/model-evaluation.json`.

Живой вызов OpenAI не проверен. Цепочка диспетчеризации проверяется с подменённым HTTP-транспортом настоящего SDK OpenAI.

Новая цепочка связывания и словоформ не проверена на реальных весах Qwen. После запуска выполните отдельный набор с ожидаемыми группами упоминаний и формами (без вызовов OpenAI):

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_persons.py | docker compose exec -T web python -
# CPU: добавьте -f compose.yaml -f compose.cpu.yaml после docker compose.
```

Старый `evaluate_model.py` предназначен для оценки детектора и точного round trip; его критерий для PERSON устарел. Проверки с подменённым генератором подтверждают логику и ограничения, но не качество решений Qwen3 1.7B.
