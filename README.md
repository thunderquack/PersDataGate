# PersDataGate

Минимальный локальный шлюз: псевдонимизирует документ и промпт перед OpenAI и восстанавливает значения в ответе.

## Запуск

Нужны Docker Compose с поддержкой `gpus: all` и NVIDIA GPU, доступный из Linux-контейнеров. CPU fallback отсутствует.

```powershell
Copy-Item .env.example .env
# Заполните OPENAI_API_KEY и OPENAI_MODEL в .env локально.
./scripts/prepare-pseudonymizer-dependencies.ps1
docker compose up -d --build
```

Подготовка выполняется в одноразовом Linux-контейнере Python 3.11.12: скачивает wheel-пакеты в `.deps/wheels`, сохраняет pip-кэш в `.deps/pip-cache` и формирует `pseudonymizer/requirements.lock.txt` с точными версиями всех зависимостей и SHA256. При первом запуске используются исходные версии из `pseudonymizer/requirements.txt`. При последующих запусках используется активный lock-файл. Lock-файл следует хранить в Git, многогигабайтные `.deps` — вне Git.

Первичная подготовка скачает CUDA wheel-пакеты заново: старый архив Docker-образа не содержит исходные `.whl`. Архив не используется новым процессом и автоматически не удаляется. Дальнейшие сборки устанавливают пакеты только из `.deps/wheels`, с проверкой хешей и отключённой сетью на шаге установки. Wheels подключаются к этому шагу через BuildKit bind mount и не сохраняются отдельным слоем в образе. Базовый образ Python и зависимости web при необходимости скачиваются отдельно.

`docker builder prune` и удаление Docker-образов не затрагивают `.deps/wheels`. Для обычной пересборки достаточно:

```powershell
./scripts/prepare-pseudonymizer-dependencies.ps1
docker compose build --no-cache
docker compose up -d
```

## Обновление зависимостей

`pseudonymizer/requirements.in` задаёт диапазоны обновлений в пределах выбранных major-версий и CUDA 12.8. Обновление выполняется отдельно от обычной сборки; рабочий lock-файл автоматически не меняется.

```powershell
./scripts/prepare-pseudonymizer-dependencies.ps1 -Mode Update
# Просмотрите .deps/candidate/requirements.lock.txt и сравните с активным lock.
docker compose build --build-arg REQUIREMENTS_LOCK=.deps/candidate/requirements.lock.txt pseudonymizer
docker compose up -d --force-recreate pseudonymizer
docker compose ps
# Дождитесь healthy, затем проверьте реальную модель:
Get-Content -Raw -Encoding UTF8 scripts/evaluate_model.py | docker compose exec -T web python -
# Проверьте также собственные документы и результаты распознавания.
./scripts/prepare-pseudonymizer-dependencies.ps1 -Mode Promote
```

`Promote` принимает проверенный кандидат и сохраняет предыдущий lock в `.deps/previous/requirements.lock.txt`. Старые wheels остаются для отката; автоматической уборки нет. Если кандидат не подошёл, активный lock остаётся прежним: пересоберите pseudonymizer обычной командой и пересоздайте контейнер. После принятия предыдущие зависимости можно вернуть, восстановив предыдущий lock и повторив подготовку и сборку.

Планировщик Windows может периодически выполнять `-Mode Update`, чтобы подготовить кандидат; запуск контейнеров и `Promote` остаются отдельными действиями после проверки. Не запускайте несколько подготовок одновременно. Если для зависимости нет совместимого бинарного wheel или версии несовместимы, подготовка завершается ошибкой, не принимая обновление.

Откройте http://localhost:8090. Модель загружается при первом запуске и кешируется в volume `model-cache`; первый запуск занимает больше времени. Без ключа и модели интерфейс доступен, но отправка в OpenAI заблокирована. После изменения `.env` выполните `docker compose up -d --force-recreate web`.

```powershell
docker compose ps
docker compose logs --tail 30 pseudonymizer
docker compose down
```

`down` сохраняет кеш модели. Не используйте `down -v`, если кеш нужно сохранить. Порт можно изменить через `WEB_PORT` в `.env`.

## Два сервиса

- `web`: FastAPI, статический интерфейс, диспетчеризация и OpenAI Responses API. Порт опубликован только на `127.0.0.1`. Документ и промпт объединяются с разделителями и обрабатываются одним вызовом.
- `pseudonymizer`: GLiNER `urchade/gliner_multi-v2.1` на CUDA, форматные правила и таблицы замен. Нет опубликованного порта и ключа OpenAI. Один процесс; GPU-инференс последовательный.

Одна кнопка выполняет `anonymize → OpenAI → deanonymize`. Справа видны параметры и полный текст запроса (`instructions` и `input`), исходный текст ответа и восстановленный текст. При сбое восстановления полученный ответ сохраняется в интерфейсе.

В OpenAI отправляется обработанный текст и фиксированная инструкция сохранять маркеры. Таблица соответствий и `mapping_id` не передаются. Используется `store=false`, без `temperature`, streaming и автоматических повторных отправок. `store=false` отключает хранение ответа для последующего извлечения API, но сам по себе не означает Zero Data Retention.

## Внутренний API

`POST http://pseudonymizer:8000/anonymize`

```json
{"text": "Иван Петров: ivan@example.org"}
```

Возвращает `mapping_id`, `text` с маркерами вида `⟦PERSON_<случайный-id>_1⟧` и `expires_at` в UTC.

`POST http://pseudonymizer:8000/deanonymize`

```json
{"mapping_id": "UUID из anonymize", "text": "Ответ с неизменёнными маркерами"}
```

Возвращает `text` и `warnings`. Восстановление выполняется одним проходом только для точных известных маркеров; неизвестные маркеры остаются без изменений. При неизвестной или истёкшей таблице — `404` с `detail: mapping_not_found`.

Таблицы живут в памяти **30 минут с момента создания**, повторное чтение не продлевает срок. Перезапуск pseudonymizer удаляет все таблицы. Для одной таблицы можно восстанавливать несколько ответов до истечения срока.

`GET /health/ready` у pseudonymizer проверяет загрузку модели; `GET /health` у web сообщает состояние конфигурации без значений ключа. Внешний API диспетчера: `POST /api/process` с `document` и `prompt`.

## Границы MVP

Только вставка текста, без файлов, OCR, истории и авторизации. Максимальный суммарный текст с разделителями — 50 000 символов. Тайм-аут внутренних HTTP-вызовов и OpenAI — 120 секунд каждый.

GLiNER ищет имена, адреса, даты рождения, номера документов и банковские идентификаторы. Правила дополняют email, телефоны, IBAN и номера документов по явному контексту. Общие даты, организации и географические названия вне адресов не входят в целевой набор. Длинный текст разбивается на перекрывающиеся фрагменты; повторные одинаковые значения получают один маркер. Разные написания и падежные формы автоматически не объединяются.

Распознавание может пропускать персональные данные или заменять лишнее. Это псевдонимизация, а не гарантия полной анонимности: контекст документа также может идентифицировать человека. Изменённые моделью маркеры автоматически не угадываются. Тексты и таблицы не записываются сервисом в файлы, логи или браузерное хранилище; содержимое страницы сохраняется только до её обновления.

## Тесты

После сборки Web тесты можно запускать в одноразовом контейнере Python 3.11:

```powershell
docker run --rm --mount "type=bind,source=$PWD,target=/checks" -w /checks persdatagate-web sh -c "python -m pip install -q -r requirements-dev.txt && python -m pytest -q"
```

Для локального запуска используйте Python 3.11, виртуальное окружение и `requirements-dev.txt`.

Unit/API-тесты используют подменённые детектор и OpenAI и не требуют Torch, GPU, ключа или платных API-вызовов. CUDA, реальная модель и качество распознавания проверяются отдельно внутри Docker.

После готовности pseudonymizer выполните оценку на синтетических русских и немецких примерах:

```powershell
Get-Content -Raw -Encoding UTF8 scripts/evaluate_model.py | docker compose exec -T web python -
```

Скрипт сообщает точные и частичные совпадения, пропуски и лишние замены, отдельно проверяя обратное восстановление. Успешный exit code означает точный round trip, а не стопроцентное качество распознавания.

Проверка 2026-10-08 на RTX 3080 Ti Laptop GPU: 22 unit/API-теста прошли. В четырёх синтетических RU/DE-примерах распознаны все 14 ожидаемых значений, обратное восстановление точное. Осталось лишнее срабатывание на отдельном слове «Москва». Это небольшой проверочный набор, а не оценка качества на реальных документах. Отчёт можно получить указанной командой; локальный результат сохранён в `artifacts/model-evaluation.json`.

Живой вызов OpenAI не проверен: локальные `OPENAI_API_KEY` и `OPENAI_MODEL` пока не настроены. Цепочка диспетчеризации проверена с подменённым HTTP-транспортом настоящего SDK OpenAI.
